¿Por qué todo se ve
pegado y apilado?

Terminaste los ejercicios de la Sesión 1 y el navbar, la tarjeta, el botón y el footer aparecen uno debajo del otro, pegados al borde izquierdo, sin espacio entre ellos. No es un error — es lo que pasa cuando el JSX no tiene un contenedor con layout alrededor. Esta guía corta explica por qué, y qué hacer al respecto.

02 / 06
La causa raíz

El fragment agrupa, pero no organiza

En el Ejercicio 1 de hoy, el App.jsx quedó así — todo envuelto en <>...</>:

frontend-react/src/App.jsx
1function App() {
2return (
3<> {/* ← el fragment empieza aquí */}
4 <nav>...</nav>
5 <div>...</div> {/* tarjeta */}
6 <button>...</button>
7 <footer>...</footer>
8</> {/* ← y termina aquí */}
9)
10}
No genera HTML
El fragment existe solo para React — cuando el navegador recibe la página, <> y </> desaparecen. No hay ningún <div> real ahí.
No admite className
Como no genera un elemento real, no se le puede poner className="p-8 flex flex-col gap-8" — no hay nada ahí para estilizar.
Solo resuelve una regla de JSX
React exige que return devuelva un único elemento — el fragment cumple esa regla técnica, nada más.
Consecuencia directa
Como no hay ningún contenedor con estilo alrededor de <nav>, <div>, <button> y <footer>, cada uno se comporta como el navegador decide por defecto: son elementos block, así que ocupan todo el ancho disponible y se apilan uno debajo del otro, sin ningún margen ni padding general.

Qué cambia — solo 2 líneas nuevas
La tarjeta (línea 18-22 original) y el botón (línea 24-26 original) — que antes estaban sueltos, directo dentro del fragment — ahora quedan envueltos por un <div className="p-8 flex flex-col items-center gap-6"> nuevo (marcado en verde). Nada del código de adentro cambia — solo se agregan esas 2 líneas: la apertura del div antes de la tarjeta, y su cierre después del botón. El <nav> y el <footer> quedan fuera de ese div a propósito — cada uno ya tiene su propio ancho completo, que es como debe ser.

Cierre

El orden llega en 3 paradas del camino

Hoy el objetivo era que cada clase utility funcionara por separado — no armar una página terminada. El layout real se construye por etapas, en lo que ya está planeado para las próximas sesiones:

01
Sesión 2

Grid y flexbox aplicados a layouts completos, breakpoints (md:, lg:) y la tarjeta de producto dentro de un grid real de catálogo — no un elemento suelto.

Sesión 3 en adelante
Componentes de React
El navbar, el footer y las tarjetas se separan en archivos propios (Navbar.jsx, Footer.jsx) — cada uno ya trae su propio contenedor bien definido.
03
Sesión 9
Migrar páginas completas
Ahí se arma el layout de página de verdad: un contenedor general, secciones bien espaciadas, todo centrado y responsive — el resultado final que hoy todavía no se ve.
Con esto en claro
Si hoy tu proyecto se ve "feo" o desordenado, no significa que algo esté mal — significa que ya sabes usar las clases utility, que era el objetivo de la Sesión 1. El orden visual llega con el layout, que es el tema de las próximas sesiones.
