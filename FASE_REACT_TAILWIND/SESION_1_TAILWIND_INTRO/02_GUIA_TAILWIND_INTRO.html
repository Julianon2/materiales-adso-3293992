Paso 1 · Instalación

Crear el proyecto con Vite

Abrimos una terminal dentro de plantilla_proyecto/ (al mismo nivel que backend/ y frontend/) y creamos el proyecto nuevo.

1

Ejecutar el comando de creación de Vite con la plantilla de React:

Terminal — dentro de plantilla_proyecto/
npm create vite@latest frontend-react -- --template react
La primera vez que usas este comando en tu máquina, npm pide instalar una herramienta extra antes de continuar:

Responde escribiendo y y Enter (o solo Enter, porque "y" ya es la opción por defecto). La terminal continúa con npx create-vite frontend-react --template react y abre un asistente interactivo:

¿Y si respondiste "No" por error? No pasa nada — solo falta hacerlo manualmente: cd frontend-react, luego npm install, y luego npm run dev. Mismo resultado, un paso más.
Paso 2 · Instalación

Instalar Tailwind CSS

Con Vite ya corriendo, dejamos esa terminal abierta y usamos otra (o detenemos con Ctrl+C) para instalar Tailwind dentro de frontend-react/.

1

Instalar Tailwind CSS y el plugin oficial de Vite:

Terminal — dentro de frontend-react/
npm install tailwindcss @tailwindcss/vite
2

Instalar el paquete no alcanza — Vite no sabe todavía que debe usarlo. Falta registrar el plugin en vite.config.js, el archivo que le dice a Vite qué herramientas usar antes de compilar cada archivo.

¿Qué es un "plugin" aquí? Un plugin de Vite es código que se engancha al proceso de compilación para hacer algo extra — react() ya está ahí desde que se creó el proyecto (le enseña a Vite a entender JSX). tailwindcss() hace lo mismo para las clases de Tailwind: sin este plugin, Vite trataría @import "tailwindcss" como CSS normal y no generaría nada.

Abrir frontend-react/vite.config.js — este es el archivo tal como lo generó Vite, con solo el plugin de React:

frontend-react/vite.config.jsactual
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

// https://vite.dev/config/
export default defineConfig({
  plugins: [react()],
})

Agregar el import de Tailwind y sumarlo al arreglo plugins — dos cambios, no hay que borrar nada:

frontend-react/vite.config.jscon Tailwind
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'
import tailwindcss from '@tailwindcss/vite'

// https://vite.dev/config/
export default defineConfig({
  plugins: [react(), tailwindcss()],
})
  • Línea 3 (nueva) — importa la función tailwindcss desde el paquete que instalamos en el Paso 1.
  • Dentro de plugins: [...] — se llama tailwindcss() junto a react(). El orden no importa, pero ambos deben estar en la misma lista.
Cómo verificar: guardar el archivo. Si el servidor (npm run dev) sigue corriendo, la terminal no debe mostrar ningún error — Vite recarga la configuración solo.
3

Abrir frontend-react/src/index.css. Ahora mismo tiene alrededor de 111 líneas de estilos que Vite agregó por defecto — no son de Tailwind, son un diseño de ejemplo genérico que ya no necesitamos:

Qué contieneEjemplo
Variables de color para tema claro y oscuro--text, --bg, --accent...
Bloque @media (prefers-color-scheme: dark)redefine esas variables en modo oscuro
Tipografía base (h1, h2, p, code)tamaños, familias de fuente, espaciados
Layout del contenedor #rootancho fijo, bordes, flexbox
¿Por qué se borra todo? Ese CSS fue pensado para la página de bienvenida que trae Vite por defecto (el logo girando). Con Tailwind, el estilo de TechStore Pro se va a escribir con clases directamente en el JSX (bg-verde, flex, etc.) — no necesitamos ninguna de estas reglas manuales, y dejarlas puede chocar con las clases de Tailwind más adelante.

Seleccionar todo el contenido del archivo (Ctrl+A), borrarlo, y dejar solo esta línea:

frontend-react/src/index.cssreemplazar todo (111 líneas → 1)
@import "tailwindcss";
4

No hace falta reiniciar nada a mano. Vite trae su propio servidor de desarrollo con recarga en vivo (igual que nodemon reinicia el backend solo al guardar) — apenas se guarda index.css, Vite ya está sirviendo la versión nueva.

¿Y si npm run dev no está corriendo? Entonces sí hay que levantarlo una vez (no es "reiniciar", es la primera vez en esta sesión de trabajo):
Terminal — solo si el servidor está apagado
npm run dev
La página que ya ves en localhost:5173 no prueba nada. Esa pantalla de bienvenida (el logo de React, "Count is 0"...) se ve así por el CSS que trae App.css — un archivo que todavía no hemos tocado. Que se vea "bien" no significa que Tailwind esté funcionando; de hecho en este punto Tailwind podría estar completamente roto y esa página se vería exactamente igual.

Por eso hace falta esta prueba: en src/App.jsx, el <h1> con el texto "Get started" es el más fácil de usar — agregarle el className de prueba:

frontend-react/src/App.jsxantes
<h1>Get started</h1>
frontend-react/src/App.jsxprueba temporal
<h1 className="text-4xl font-bold text-blue-600">Get started</h1>
Confirmado: esas tres clases (text-4xl, font-bold, text-blue-600) no existen en App.css — solo pueden venir de Tailwind. Al guardar, "Get started" se ve grande, en negrita y azul sin que hicieras nada más que guardar — esa es la primera confirmación real de que el Paso 2 y el Paso 3 quedaron bien hechos. Si no cambia nada, revisa que vite.config.js tenga tailwindcss() en plugins y que index.css tenga el @import. Una vez confirmado, se puede quitar ese className de prueba — ya cumplió su función.
Error común: si las clases no aplican ningún estilo, revisa que src/main.jsx tenga import './index.css' — Vite lo agrega por defecto, pero si se borró por error, Tailwind nunca se carga.
Paso 3 · Configuración

Configurar los colores del proyecto

TechStore Pro ya tenía sus colores definidos como variables CSS en frontend/css/styles.css (--sena-verde, --sena-naranja, etc.). En Tailwind 4 se definen igual, con @theme dentro del mismo index.css — sin archivo de configuración aparte.

1

Agregar el bloque @theme justo debajo del import de Tailwind:

frontend-react/src/index.cssagregar
@import "tailwindcss";

@theme {
  --color-verde: #39a900;
  --color-verde-dark: #2d8400;
  --color-naranja: #ff6b00;
  --color-azul: #3b82f6;
  --color-texto: #1a1a2e;
  --color-texto-dim: #64748b;
}
2

Ya se pueden usar como clases normales de Tailwind, con el nombre después de color-:

Dónde probarlo: el mismo <h1> de src/App.jsx que se usó en el Paso 2 sirve otra vez — solo cambia el className:

Cómo verificar: al guardar, el fondo detrás de "Get started" debe verse verde institucional del SENA (#39a900, el mismo de la barra superior de esta guía) — no un verde genérico de Tailwind como bg-green-600, que se ve más brillante/azulado. Si el verde coincide con los swatches de arriba, el @theme quedó bien configurado. Ese className de prueba también se puede quitar después.

Paso 5 · Aplicación real

Migrar el Navbar de TechStore Pro

Primera pieza real del proyecto reconstruida con Tailwind — comparamos contra el navbar actual de frontend/index.html.

1

Abrir src/App.jsx, seleccionar todo el archivo (Ctrl+A) y borrarlo por completo — incluyendo los imports de arriba (useState, heroImg, reactLogo, viteLogo, ./App.css) y todo el contenido de práctica de los pasos anteriores. Ya no se necesita nada de eso.

Este nuevo App.jsx no importa useState ni ningún ícono/imagen porque el navbar de hoy no los usa — si un componente no necesita algo, no se importa.

Pegar esto en su lugar, como contenido completo y único del archivo:

frontend-react/src/App.jsxreemplazar todo
function App() {
  return (
    <nav className="flex items-center justify-between px-8 py-4 bg-white border-b border-slate-200">
      <div className="text-xl font-extrabold text-verde">
        TechStore Pro
      </div>
      <ul className="flex gap-6 text-sm font-semibold text-texto-dim">
        <li>Inicio</li>
        <li>Productos</li>
        <li>Nosotros</li>
        <li>Contacto</li>
      </ul>
      <button className="bg-verde text-white py-2 px-5 rounded-lg font-bold text-sm">
        Ingresar
      </button>
    </nav>
  )
}

export default App
Cómo verificar: en localhost:5173 debe verse un navbar horizontal con el nombre "TechStore Pro" en verde a la izquierda, los 4 links al centro/derecha, y el botón "Ingresar" en verde sólido — mismo look que el navbar actual de frontend/, ahora sin una sola línea de CSS manual.
¿Qué es App.jsx en este punto de la fase?
Hoy App.jsx funciona como ese único archivo donde se mete todo para practicar — el equivalente al <body> de un HTML. Por eso el navbar, y cualquier ejercicio extra, se escriben todos ahí mismo, uno debajo del otro, sin separar nada en componentes propios.

Eso va a cambiar en la Sesión 4 (Props y composición de componentes): ahí el navbar se va a mover a su propio archivo (Navbar.jsx) y App.jsx pasará a cumplir su rol real — ensamblar componentes hijos en vez de contener todo el código directamente. Por ahora, con un solo componente, no hace falta esa separación.
