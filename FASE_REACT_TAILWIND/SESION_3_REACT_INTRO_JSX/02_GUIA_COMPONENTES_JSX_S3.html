Tu primer componente de React: Navbar.jsx

SENA ADSO · Ficha 3293992 · Noviembre 2026

Sigue cada paso en orden. No avances al siguiente hasta que el anterior funcione y hayas marcado el check.
El problema que resolvemos hoy
Al terminar la Sesión 2, App.jsx quedó con todo escrito en un solo return: el navbar, las tarjetas del catálogo y el footer, uno detrás del otro:
frontend-react/src/App.jsx — estado actual (resumido)antes de hoy
function App() {
  return (
    <main className="max-w-6xl mx-auto px-6 py-10 flex flex-col gap-10">
      <nav ...>...</nav>              {/* 15 líneas */}
      <section ...>...</section>      {/* 4 tarjetas, ~40 líneas */}
      <footer ...>...</footer>        {/* 4 líneas */}
    </main>
  );
}

export default App;
Funciona, pero un archivo así crece sin control: cada página nueva de TechStore Pro necesitaría copiar el navbar completo. Hoy lo separas en su propio componente, sin cambiar nada de cómo se ve.
¿Qué construimos hoy?
Sacar el navbar de App.jsx y convertirlo en su propio componente

Creas src/Navbar.jsx, mueves el navbar adentro de una función, lo exportas, lo importas de vuelta en App.jsx y lo usas como si fuera una etiqueta HTML: <Navbar />. El resultado visual no cambia — lo que cambia es la organización del código.

Paso 1
Crear src/Navbar.jsx con el navbar movido desde App.jsx
Paso 2
export default Navbar — decirle al archivo qué entrega
Paso 3
import Navbar + usar <Navbar /> dentro de App.jsx

Paso 0 · Antes de empezar

Confirmar que el proyecto corre

5 min

Hoy no se instala nada: React viene incluido desde que Vite creó frontend-react/ en la Sesión 1 (plantilla --template react). Solo hace falta tener el servidor de desarrollo encendido.

1

Abre la carpeta frontend-react en VS Code y, en la terminal integrada (Ctrl + ñ o menú Terminal → New Terminal), ejecuta:

terminal — dentro de frontend-react/ejecutar
npm run dev
ParteQué hace
npmEl gestor de paquetes de Node.js — es quien ejecuta los scripts del proyecto
run"Ejecuta un script" que está definido en package.json, en la sección "scripts"
devEl nombre del script: en tu package.json dice "dev": "vite", o sea, arranca el servidor de Vite con recarga en vivo

Paso 1 · Componente

Crear src/Navbar.jsx

20 min

Un componente nuevo empieza como un archivo nuevo. Vas a crear Navbar.jsx al lado de App.jsx, dentro de src/.

1

En el explorador de VS Code, clic derecho sobre la carpeta frontend-react/src/ → New File, y nómbralo Navbar.jsx (en el mismo lugar donde está App.jsx).

El archivo empieza con mayúscula porque el componente que va adentro también empieza con mayúscula. Es una convención (no una regla obligatoria de JavaScript), pero todo el ecosistema de React la sigue: un archivo = un componente = el mismo nombre.
2

Mover el navbar de un archivo al otro — no se copia dejando el original: se traslada completo.

AcciónDónde
1. CortarEn App.jsx, selecciona el bloque completo desde <nav hasta </nav> y córtalo con Ctrl + X. Ese espacio queda vacío en App.jsx
2. PegarEn Navbar.jsx, pégalo con Ctrl + V. En el punto 3 lo envuelves en una función

El bloque que se mueve es este — el mismo navbar que viene funcionando desde la Sesión 1, con el hidden md:flex de la Sesión 2:

Bloque que se mueve de App.jsx a Navbar.jsxcortar y pegar
<nav className="flex items-center justify-between px-8 py-4 bg-white border-b border-slate-200">
  <div className="text-xl font-extrabold text-primario">
    TechStore Pro
  </div>
  <ul className="hidden md:flex gap-6 text-sm font-semibold text-texto-dim">
    <li>Inicio</li>
    <li>Productos</li>
    <li>Nosotros</li>
    <li>Contacto</li>
    <li>Registro</li>
  </ul>
  <button className="bg-primario text-white py-2 px-5 rounded-lg font-bold text-sm">
    Login
  </button>
</nav>
Si tu navbar quedó distinto (otros textos en los links, "Ingresar" en vez de "Login", text-verde en vez de text-primario, o sin el hidden md:flex), mueve el tuyo real. Lo importante es trasladar exactamente lo que ya tienes, no reescribirlo.
No te preocupes si localhost:5173 deja de mostrar el navbar en este momento: es lo esperado. En el Paso 3 vuelve a aparecer, con <Navbar /> en el lugar donde estaba.
3

Envuelve ese bloque pegado en Navbar.jsx dentro de una función llamada Navbar que lo devuelve con return. Así queda convertido en componente:

frontend-react/src/Navbar.jsxcontenido completo
function Navbar() {
  return (
    <nav className="flex items-center justify-between px-8 py-4 bg-white border-b border-slate-200">
      <div className="text-xl font-extrabold text-primario">
        TechStore Pro
      </div>
      <ul className="hidden md:flex gap-6 text-sm font-semibold text-texto-dim">
        <li>Inicio</li>
        <li>Productos</li>
        <li>Nosotros</li>
        <li>Contacto</li>
        <li>Registro</li>
      </ul>
      <button className="bg-primario text-white py-2 px-5 rounded-lg font-bold text-sm">
        Login
      </button>
    </nav>
  );
}
ParteQué es
functionPalabra de JavaScript para declarar una función
NavbarEl nombre del componente — con mayúscula, para que React lo reconozca como componente
()Los paréntesis de la función, vacíos porque por ahora no recibe datos (eso llega con las props en la Sesión 4)
return ( ... );Lo que la función entrega cuando React la llama: el JSX del navbar
( ) alrededor del JSXNo son obligatorios, pero permiten escribir el JSX en varias líneas sin errores
<nav> ... </nav>El único elemento raíz del return — cumple la regla de JSX de "un solo elemento raíz"
Si la indentación queda desordenada al pegar, formatea el archivo con Shift + Alt + F.
Cómo verificar: el archivo Navbar.jsx existe y tiene la función Navbar con el JSX del navbar adentro. Todavía no se usa en ningún lado — es normal, se conecta en el Paso 3.
Paso 2 · Conexión

Exportar el componente con export default

10 min

Por ahora, Navbar solo existe dentro de Navbar.jsx: ningún otro archivo puede verlo. export default es lo que lo deja disponible para importarlo desde otro archivo.

1

Al final de Navbar.jsx, después de la llave } que cierra la función, deja una línea en blanco y agrega:

frontend-react/src/Navbar.jsxagregar al final
function Navbar() {
  return (
    <nav className="...">...</nav>
  );
}

export default Navbar;
TrozoQué significa
exportMarca algo de este archivo como disponible para otros archivos
defaultIndica que es "lo principal que entrega este archivo" — por eso solo puede haber un export default por archivo
NavbarEl nombre de la función que se exporta — debe coincidir exactamente con function Navbar(), mismas mayúsculas
;Cierra la instrucción. Es opcional en JavaScript; aquí se usa porque tu App.jsx también lo usa
Esto ya lo usaste desde la Sesión 1 sin saberlo: la última línea de App.jsx siempre fue export default App;. Es exactamente el mismo mecanismo, ahora en un archivo tuyo.
Cómo verificar: Navbar.jsx completo tiene la función Navbar y, al final, export default Navbar; — sin subrayados rojos de sintaxis en VS Code.
Paso 3 · Uso

Importar y usar <Navbar /> en App.jsx

15 min

Ahora en App.jsx: traer el componente con import y usarlo en el espacio vacío que quedó, como si fuera una etiqueta HTML.

1

En la primera línea de App.jsx, antes de function App(), agrega el import:

frontend-react/src/App.jsxagregar al inicio
import Navbar from './Navbar.jsx';

function App() {
  ...
TrozoQué significa
import"Trae algo de otro archivo"
NavbarEl nombre con el que lo vas a usar en este archivo. Con export default, este nombre lo elige quien importa — se usa el mismo por claridad
from"desde..." — separa el nombre de la ruta
'./Navbar.jsx'La ruta al archivo: ./ significa "en esta misma carpeta" (src/), y luego el nombre exacto del archivo
Abre src/main.jsx un momento: ahí está import App from './App.jsx' y, más abajo, <App />. Es la misma línea que acabas de escribir, un nivel más arriba.
2

Dentro del return (...) de App.jsx, en el espacio vacío que quedó después de <main ...> — donde estaba el <nav>...</nav> antes de cortarlo — escribe:

frontend-react/src/App.jsxescribir en el espacio vacío
<Navbar />
ParteQué significa
<NavbarUsa el componente como si fuera una etiqueta HTML propia — React lo reconoce por la mayúscula inicial y ejecuta la función Navbar()
/>Se auto-cierra porque no tiene contenido adentro — igual que <img />

App.jsx completo debe quedar así (las tarjetas y el footer no cambian, se muestran resumidos):

frontend-react/src/App.jsxcómo queda
import Navbar from './Navbar.jsx';

function App() {
  return (
    <main className="max-w-6xl mx-auto px-6 py-10 flex flex-col gap-10">
      <Navbar />

      <section className="grid grid-cols-1 sm:grid-cols-2 md:grid-cols-2 lg:grid-cols-3 gap-6">
        {/* Tarjetas 1 a 4 — sin cambios */}
      </section>

      <footer className="flex flex-col md:flex-row justify-between items-center gap-2 md:gap-0 p-6 bg-texto text-white">
        <p>© 2026 TechStore Pro</p>
        <p className="text-sm">Hecho con Tailwind CSS</p>
      </footer>
    </main>
  );
}

export default App;
Si tu <section> no tiene sm:grid-cols-2 (era un ejercicio opcional de la Sesión 2), no lo agregues ahora: deja tu catálogo tal como está. Hoy no se toca.
Cómo verificar: en localhost:5173, el navbar se ve exactamente igual que antes — mismo diseño, mismo texto, mismo comportamiento responsive (hidden md:flex). Nada cambia visualmente: solo la organización del código.
Paso 4 · Verificación

Confirmar que todo sigue funcionando

15 min

El objetivo de hoy no es cambiar el diseño: es reorganizar el código sin romper nada. Esta verificación confirma justamente eso.

1

En localhost:5173, revisa visualmente: el navbar (logo, links, botón), el grid de tarjetas y el footer deben verse exactamente igual que al terminar la Sesión 2. Achica la ventana: en celular los links del navbar se siguen ocultando.

2

Abre la consola del navegador (F12 → pestaña Console) y mira la terminal donde corre npm run dev. Ninguna de las dos debe mostrar errores rojos. Si aparece alguno, búscalo en esta tabla:

Mensaje (o síntoma)Causa probableCómo se arregla
Navbar is not definedFalta el import en App.jsx, o el nombre no coincideRevisa la primera línea: import Navbar from './Navbar.jsx';, con N mayúscula
Failed to resolve import "Navbar.jsx"A la ruta le falta el ./ del inicio, o el nombre del archivo está mal escritoLa ruta debe ser exactamente './Navbar.jsx', igual al nombre real del archivo
does not provide an export named 'default'Falta export default Navbar; al final de Navbar.jsxVuelve al Paso 2
Adjacent JSX elements must be wrapped...Quedaron dos elementos sueltos en un return (por ejemplo, se pegó algo fuera del <nav>)El return de Navbar debe tener solo el <nav> como raíz
El navbar sale dos vecesSe copió en vez de cortar: el <nav> original sigue en App.jsxBorra el <nav>...</nav> de App.jsx; deja solo <Navbar />
No sale el navbar y la consola dice que <navbar> no es reconocidaSe escribió <navbar /> en minúscula: React lo trata como etiqueta HTML desconocidaEscríbelo con mayúscula: <Navbar />
3

Prueba de conexión: cambia temporalmente un texto dentro de Navbar.jsx (por ejemplo "Login" por "Entrar"), guarda con Ctrl + S y mira el navegador sin tocar App.jsx. Después déjalo como estaba.

Cómo verificar: el cambio aparece al instante en localhost:5173 gracias a la recarga en vivo de Vite. Eso confirma que el componente está realmente separado y conectado: App.jsx no tiene el navbar escrito, solo lo usa.
