Concepto
Concepto

¿Qué es React, exactamente?

Hasta hoy usaste React de forma indirecta: Vite lo instaló, pero todo lo que escribiste (navbar, tarjetas, footer) fue HTML con clases de Tailwind. React es la librería que construye ese HTML de forma dinámica, a partir de código JavaScript.

Una librería, no un lenguaje
React es JavaScript — no es un lenguaje nuevo. Es un conjunto de herramientas para construir interfaces sin escribir a mano document.createElement() una y otra vez.
Todo se arma con componentes
En vez de un solo HTML gigante, la interfaz se divide en piezas pequeñas y reutilizables. Cada pieza es un componente: un navbar, una tarjeta, un footer.
Actualiza solo lo que cambia
Cuando algo cambia en pantalla (un contador, un carrito), React no recarga toda la página: actualiza solo esa parte. Lo verás en las dos slides siguientes (Virtual DOM).
Lo que ya sabías, con otro nombre
function App() { return (...) } ya es un componente de React — lo escribiste desde la Sesión 1 sin llamarlo así. Hoy le ponemos nombre a lo que ya venías haciendo y aprendes a crear un segundo.
¿Hay que instalar React hoy?
No. Cuando en la Sesión 1 corriste npm create vite@latest frontend-react -- --template react, la opción --template react ya agregó react y react-dom como dependencias en package.json. Por eso App.jsx fue un componente desde el primer día.
Un poco de historia
React nació dentro de Facebook para resolver un problema muy concreto: interfaces enormes (el muro de noticias, los mensajes, las notificaciones) que cambiaban todo el tiempo y se volvían imposibles de mantener a mano. La idea que propuso fue sencilla: describe cómo debe verse la pantalla y deja que React se encargue de actualizarla. Se publicó como código abierto en 2013 y hoy es una de las librerías de interfaz más usadas del mundo.

El problema
El problema

El patrón de JavaScript puro... y su costo oculto

En proyectos de JavaScript puro (sin React), una forma muy común de pintar una lista que cambia — por ejemplo, el resultado de un buscador de productos — es reemplazar todo el contenido del contenedor cada vez que algo cambia:

main.js — JavaScript puro, sin React
1// Cada vez que el usuario escribe en el buscador...
2const gridTarjetas = document.querySelector('#grid-tarjetas');
3
4gridTarjetas.innerHTML = productos.map(crearTarjeta).join('');
LíneaQué hace
document.querySelector('#grid-tarjetas')Busca en la página el contenedor de las tarjetas
productos.map(crearTarjeta)Convierte cada producto en un texto de HTML (una tarjeta)
.join('')Une todos esos textos en uno solo
.innerHTML =Borra todo lo que había dentro del contenedor y pone el HTML nuevo
Lo que realmente pasa en la línea 4
Aunque solo cambie una tarjeta (por ejemplo, el usuario filtra y quedan 5 de 6), .innerHTML = borra las 6 tarjetas completas del DOM real y las vuelve a crear desde cero — imágenes, botones, textos, todo. El navegador tiene que recalcular estilos y volver a pintar las 6, no solo la que cambió.
Simulación — cada vez que se escribe en el buscador
Las 6 tarjetas parpadean todas: se destruyen y se vuelven a crear, aunque solo 1 tuviera que cambiar.
Este patrón no está "mal"
Para 6 tarjetas es imperceptible — por eso funciona en proyectos pequeños. El problema aparece cuando la interfaz crece: cientos de elementos y actualizaciones frecuentes (un contador, un chat, un formulario con validación en vivo, el carrito de TechStore Pro). Ahí ese "recrear todo" sí se nota, y es justo lo que resuelve el Virtual DOM.

Concepto
Concepto

Virtual DOM — la idea, no la implementación

No vas a programar el Virtual DOM: React lo hace por ti. Pero entender la idea explica por qué React resuelve el problema de la slide anterior.

El mismo cambio, pero con React
Solo la tarjeta que realmente cambió se actualiza — las otras 5 ni se tocan.
JavaScript puro con innerHTML
innerHTML = reemplaza TODO el contenido del contenedor — no hay forma de decirle "cambia solo esta parte".
VS
Con Virtual DOM (React)
React guarda una copia ligera del DOM en memoria. Cuando algo cambia, compara la copia vieja con la nueva, calcula la diferencia mínima y actualiza solo esa parte en el DOM real.
Analogía: el juego de las diferencias
Imagina dos dibujos casi iguales. En vez de volver a pintar el dibujo completo, buscas las diferencias y corriges solo esas. El Virtual DOM es el "borrador" donde React compara el antes y el después, antes de tocar la página real.
No se programa manualmente
El Virtual DOM es interno de React: nunca vas a escribir código que lo maneje directamente, ni un querySelector para pintar la interfaz. Solo necesitas saber que existe y por qué React puede actualizar la pantalla sin recargar la página.

JSX — HTML dentro de JavaScript

Vienes escribiendo JSX desde la Sesión 1 sin saber su nombre: es la sintaxis que mezcla HTML con JavaScript dentro de un componente. Parece HTML, pero tiene algunas reglas propias.

frontend-react/src/App.jsx — esto ya ES JSX
1function App() {
2return (
3 <main className="max-w-6xl mx-auto ...">
4 <nav className="flex ...">...</nav>
5 <img src="..." />
6 {/* Tarjeta 1 */}
7 </main>
8);
9}
LíneaQué es
1function App() — una función de JavaScript normal, con nombre en mayúscula
2 y 8return ( ... ); — lo que la función entrega: un bloque de JSX entre paréntesis
3 y 7<main> — el único elemento raíz que envuelve todo
4className en vez de class
5<img /> se cierra con />
6{/* ... */} — así se escribe un comentario dentro de JSX
Regla de JSXPor quéDónde ya la usaste
Un único elemento raíz por returnUna función solo puede devolver una cosa: JSX no permite dos elementos sueltos uno al lado del otroEl fragment <>...</> de la Sesión 1 y el <main> de la Sesión 2
className en vez de classclass es palabra reservada de JavaScript (sirve para crear clases); JSX usa el nombre de la propiedad del DOMTodas las clases de Tailwind
Toda etiqueta se cierra<img />, no <img> — en HTML se perdona, en JSX es errorLas imágenes de las tarjetas
{ } para JavaScript dentro del JSXCualquier variable o expresión va entre llavesLos comentarios {/* Tarjeta 1 */}; desde la Sesión 4 lo usarás para datos
Mayúscula = componente, minúscula = HTMLAsí React sabe si <nav> es una etiqueta del navegador o si <Navbar /> es una función tuyaHoy, por primera vez, con <Navbar />
Qué te llevas para la práctica de hoy
Cuando muevas el navbar a Navbar.jsx, su return debe tener un solo elemento raíz — el propio <nav> — y todas las reglas de esta tabla se siguen cumpliendo igual, porque el bloque se traslada tal cual.

Concepto
Concepto

Un componente es una función que devuelve JSX

Esa es toda la definición. Un componente de React no es más que una función de JavaScript normal, con dos reglas simples.

Empieza con mayúscula
function Navbar(), no function navbar(). Así React distingue un componente tuyo de una etiqueta HTML normal.
Devuelve JSX
Su return entrega un bloque de JSX con un solo elemento raíz. Eso es lo que React dibuja en pantalla cuando usas el componente.
Analogía: piezas de LEGO

Una página hecha con React se arma como una construcción de LEGO: hay piezas pequeñas (un botón, una tarjeta), piezas medianas que juntan varias pequeñas (un navbar, un catálogo) y una pieza grande que lo ensambla todo (App).

La ventaja es la misma que con los LEGO: si una pieza se daña, cambias solo esa; si necesitas la misma pieza en otro lugar, la vuelves a usar sin fabricarla de nuevo. Hoy fabricas tu primera pieza propia: Navbar.
