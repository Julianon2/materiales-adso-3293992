Sesión 3 · Guía 4

Subir tu proyecto a GitHub

SENA ADSO · Ficha 3293992 · Noviembre 2026

Esta guía no modifica tu código — solo lo sube a GitHub. Hazla cuando ya tengas el proyecto frontend-react corriendo (Sesión 1 en adelante).
¿Qué vamos a hacer?
Cada aprendiz crea su propio repositorio y agrega al instructor como colaborador

Cada uno tendrá su propio repositorio en su propia cuenta de GitHub — nadie comparte repositorio con otro compañero. Al final, agregas a tu instructor como colaborador para que pueda revisar tu avance directamente desde GitHub, sin que le envíes archivos.

Git local
Convertir la carpeta del proyecto en un repositorio y guardar el primer "commit"
GitHub
Crear el repositorio vacío en tu cuenta y conectarlo con tu carpeta local
Colaborador
Agregar a tu instructor para que pueda ver tu proyecto sin pedírtelo por otro medio
Paso 1

Verificar e iniciar git

5 min

Git es el programa que guarda el historial de cambios de tu proyecto. GitHub es la página web donde ese historial se guarda en línea. Primero confirmamos que Git está instalado y luego activamos el seguimiento en tu carpeta.

1

Abre una terminal dentro de tu carpeta frontend-react (en VS Code: Terminal → Nueva Terminal) y verifica que Git esté instalado:

Terminalverificar
git --version
Si no reconoce el comando, instala Git desde git-scm.com/downloads y vuelve a abrir la terminal.
2

Si es la primera vez que usas Git en tu computador, identifícate (solo una vez, no se repite por proyecto):

Terminalsolo la primera vez
git config --global user.name "Tu Nombre Completo"
git config --global user.email "tu-correo@ejemplo.com"
3

Dentro de la carpeta de tu proyecto, inicializa el repositorio local:

Terminal — dentro de frontend-react/iniciar
git init
ComandoQué hace
git initCrea una carpeta oculta .git — a partir de aquí, Git puede ver los cambios de tus archivos
Cómo verificar: el mensaje dice algo como "Initialized empty Git repository" y aparece una carpeta .git (oculta) dentro de tu proyecto.
Paso 2

.gitignore y primer commit

5 min

Antes de subir nada, le decimos a Git qué carpetas NO debe guardar — como node_modules, que es pesada y se puede regenerar con un comando.

1

Si tu proyecto viene de Vite, probablemente ya existe un archivo .gitignore. Confirma que contenga al menos esta línea (ábrelo en VS Code):

frontend-react/.gitignoredebe existir
node_modules
dist
.env
Si subes node_modules por error, el repositorio queda enorme y lento. Vite ya crea el .gitignore correcto al generar el proyecto — solo confírmalo, no lo borres.
2

Agrega todos los archivos al "área de preparación" y guarda el primer commit (una foto del estado actual del proyecto, con un mensaje describiéndola):

Terminalguardar cambios
git add .
git commit -m "Primer commit: proyecto TechStore Pro con Tailwind y React"
ComandoQué hace
git add .Marca todos los archivos de la carpeta (menos los del .gitignore) para guardarlos
git commit -m "..."Guarda esa foto del proyecto con un mensaje que explica qué contiene
Cómo verificar: el commit muestra cuántos archivos cambiaron (ej. "15 files changed"). Si corres git status después, debe decir "nothing to commit, working tree clean".
Paso 3

Crear el repositorio en GitHub

5 min

Ahora creamos el "contenedor" vacío en GitHub, en tu propia cuenta, donde va a vivir tu proyecto en línea.

1

Entra a tu cuenta en github.com (crea una gratis si todavía no tienes) y ve a github.com/new.

2

Completa el formulario así:

CampoQué poner
Repository nameAlgo claro, por ejemplo techstore-pro-react
DescriptionOpcional — ej. "Proyecto TechStore Pro, Fase React y Tailwind, ficha 3293992"
Public / PrivatePublic — así tu instructor puede verlo sin necesitar invitación para solo mirar
Initialize with README, .gitignore, licenseDéjalos todos sin marcar — tu proyecto ya tiene archivos, y mezclar los dos orígenes complica el primer push
Si marcas "Add a README", GitHub crea un commit en el repositorio remoto que tu carpeta local no tiene — eso complica el primer push. Por eso lo dejamos vacío.
3

Haz clic en Create repository. GitHub te muestra una página con comandos — los vas a usar en el Paso 4, no los cierres todavía.

Paso 4

Conectar y subir (push)

5 min

Le decimos a tu repositorio local dónde está su "destino" en GitHub, y subimos el commit del Paso 2.

1

En la página de tu repositorio nuevo, copia la URL que termina en .git (aparece junto a "…or push an existing repository from the command line"). En tu terminal:

Terminalconectar
git remote add origin https://github.com/TU-USUARIO/techstore-pro-react.git
git branch -M main
git push -u origin main
Reemplaza TU-USUARIO y el nombre del repositorio por los tuyos reales — esa URL es la que GitHub te mostró al crear el repositorio, cópiala tal cual.
ComandoQué hace
git remote add origin ...Guarda la dirección de tu repositorio en GitHub con el nombre "origin"
git branch -M mainAsegura que tu rama principal se llame "main", igual que en GitHub
git push -u origin mainSube tu commit a GitHub y deja la conexión guardada para la próxima vez
2

Si la terminal te pide iniciar sesión, sigue las instrucciones en pantalla (puede abrir el navegador para autenticarte).

Cómo verificar: recarga la página de tu repositorio en GitHub — deben aparecer todos tus archivos (menos node_modules).
Paso 5

Agregar a tu instructor como colaborador

3 min

Como el repositorio es público, tu instructor ya puede verlo con solo el enlace. Agregarlo como colaborador es un paso adicional para que, si lo necesita, también pueda comentar o hacer cambios directamente.

1

En la página de tu repositorio en GitHub, ve a Settings → Collaborators (puede pedirte tu contraseña de nuevo).

2

Haz clic en Add people y escribe el usuario de tu instructor:

Usuario de GitHub a invitarinstructor
Jtrujillosena
3

Confirma la invitación. El instructor recibirá una notificación y debe aceptarla desde su cuenta para quedar activo como colaborador.

Cómo verificar: en Settings → Collaborators aparece Jtrujillosena con estado "Pending" (hasta que el instructor acepte) o ya como colaborador activo.
Cierre

Checklist de la Guía 4

  • git init hecho y primer commit guardado sin incluir node_modules
  • Repositorio creado en GitHub, público, vacío (sin README automático)
  • git push exitoso — los archivos se ven en la página del repositorio
  • Jtrujillosena agregado como colaborador en Settings → Collaborators
