SLIDE 01 / 14
Concepto

¿Qué es Tailwind CSS?

Un framework CSS "utility-first": en vez de escribir clases con nombres propios (.tarjeta, .boton-primario) y luego definir sus estilos en un archivo aparte, usas clases pequeñas y ya definidas (flex, p-4, bg-verde-600) directamente en el HTML.

¿Qué es exactamente una "clase utility"?

Es una clase CSS que ya viene escrita y lista para usar, y que hace una sola cosa muy específica — nunca combina varias reglas como haría una clase tradicional. No la escribes tú ni le pones nombre: ya existe dentro de Tailwind, lista para usarse en el className del elemento.

p-4 → padding: 1rem
text-white → color: white

La diferencia con una clase tradicional (como .tarjeta) es que esa sí la inventas tú, le pones el nombre que quieras, y adentro agrupas varias reglas CSS juntas. Una clase utility es más pequeña y siempre hace lo mismo, sin importar en qué proyecto la uses.

Por eso se combinan varias en un mismo elemento — className="flex p-4 bg-verde" — para lograr un diseño completo.

Origen — ¿de dónde salió Tailwind?

Tailwind CSS fue creado por Adam Wathan (junto a Jonathan Reinink, Steve Schoger y David Hemphill) y lanzado en noviembre de 2017. Adam venía de años escribiendo CSS "tradicional" y notó un patrón: en cada proyecto terminaba reinventando las mismas clases (.card, .btn) una y otra vez, y esas clases crecían sin control con el tiempo — el problema real que resolvió no fue "escribir menos CSS", sino dejar de inventar nombres y mantener un archivo que nadie se atrevía a tocar.

Hoy Tailwind Labs (la empresa detrás) también mantiene Tailwind UI y Headless UI, y el framework pasó a la versión 4 en 2025 con un motor de compilación mucho más rápido — la versión que instalamos hoy.

Clases pequeñas y combinables
Cada clase hace una sola cosa: flex activa flexbox, p-4 agrega padding. Se combinan para lograr cualquier diseño.
El estilo vive junto al HTML
No saltas entre index.html y styles.css — ves la estructura y el diseño en el mismo lugar.
Solo el CSS que usas
Tailwind analiza tu código y genera un archivo final con únicamente las clases que realmente usaste — nada de código muerto.
Estándar de la industria
Empresas como GitHub, Shopify y OpenAI lo usan en producción. Es la habilidad de CSS más pedida en ofertas de trabajo hoy.

SLIDE 02 / 14
Herramientas nuevas

¿Qué vamos a instalar hoy?

Hasta ahora el frontend de TechStore Pro era HTML/CSS/JS puro, sin instalación de nada. Hoy nace un proyecto nuevo — frontend-react/ — con dos herramientas nuevas.

Vite
Una herramienta que arma el "esqueleto" del proyecto y lo sirve en el navegador con recarga instantánea al guardar cambios. Reemplaza a Live Server para proyectos modernos.
Tailwind CSS
El framework de utilidades que vimos en la diapositiva anterior. Se conecta a Vite para generar el CSS final automáticamente.

Primero, ¿dónde va a vivir frontend-react/?

plantilla_proyecto/ — árbol de carpetas
plantilla_proyecto/
├──backend/           // ya existe — no se toca
├──frontend/          // ya existe — HTML viejo, sigue igual
└──frontend-react/   ← NUEVA
no existe todavía — la crea el comando de la próxima slide
¿Por qué un proyecto nuevo y no modificar frontend/?
frontend/ (el HTML actual) sigue funcionando tal cual durante toda la fase — es nuestra red de seguridad. frontend-react/ crece en paralelo, sesión a sesión, y solo al final (Sesión 20) reemplaza al viejo.
El backend no cambia
Todo esto es 100% frontend. El servidor Express, MongoDB, las rutas y modelos siguen exactamente igual en backend/ — no se toca ni una línea.
Origen — ¿de dónde salió Vite?

Vite fue creado por Evan You — el mismo creador de Vue.js — y lanzado en 2020. Nació de una frustración concreta: con las herramientas de esa época (como Webpack), cada vez que guardabas un cambio en un proyecto grande, esperabas varios segundos a que todo se re-empaquetara antes de ver el resultado.

Vite resuelve esto aprovechando los módulos ES que el navegador ya entiende de forma nativa: en desarrollo no empaqueta nada de entrada, solo sirve los archivos que realmente se piden — por eso arranca casi al instante y recarga en milisegundos. Su nombre viene del francés "rápido" (se pronuncia "vit").

Hoy ya no es exclusivo de Vue: lo usan proyectos de React (como el nuestro), Svelte, y es la base de frameworks como Astro y SvelteKit.

Dato curioso: Tailwind también se puede usar sin instalar nada

Existe una forma de probar Tailwind en segundos, sin Node ni npm: agregar una sola línea en el <head> de cualquier HTML — <script src="https://cdn.tailwindcss.com"></script> — y ya tienes todas las clases utility disponibles. Es el llamado Play CDN, útil para una demo rápida o un CodePen.

No es lo que usamos hoy en TechStore Pro, porque ese script genera el motor completo de Tailwind dentro del navegador de cada visitante (archivo pesado, sin optimizar) y no guarda una configuración propia del proyecto. Lo que instalamos con Vite en la próxima slide compila en nuestra máquina y entrega solo el CSS final, mínimo, listo para producción — la diferencia entre "probar" y "construir".

Antes de instalar

Glosario rápido: 4 palabras que vas a escuchar hoy

No hace falta memorizarlas — solo tenerlas a la mano la primera vez que aparezcan en la instalación. La idea de fondo ya la conoces de la Slide 2: una clase utility es algo ya escrito y listo para usar, no algo que inventas tú.

Utility-first
La idea central de Tailwind: construir el diseño combinando clases pequeñas y ya listas (p-4, flex) en vez de inventar nombres propios.
Build tool (herramienta de build)
Un programa que transforma el código que escribimos (JSX, Tailwind) en archivos que el navegador entiende. Vite es la que usamos hoy.
Linter
Revisa el código mientras escribes y avisa errores de sintaxis antes de correrlo. No cambia cómo se ve la app, solo ayuda a detectar fallos más rápido.
Plugin
Una pieza que se conecta a una herramienta para darle una función nueva. @tailwindcss/vite es el plugin que le enseña a Vite a procesar Tailwind.
No necesitas aprenderlas de memoria
Estas 4 palabras van a aparecer en la instalación de las próximas slides. Si en algún momento te pierdes, vuelve a esta slide con el botón del sidebar — para eso quedó aquí.

La idea clave de este flujo
Este proceso completo (escanear → generar CSS → recargar el navegador) pasa automáticamente cada vez que guardas un archivo, mientras npm run dev está corriendo. No hay que ejecutar ningún comando extra — por eso Tailwind se siente instantáneo mientras programas. SLIDE 05 / 14
Instalación · Paso 1 de 3

Ejecutar el comando de creación

¿Qué es Vite exactamente?
Vite (se pronuncia "vit", del francés "rápido") es una herramienta de build: convierte el código que escribimos (JSX, módulos, Tailwind) en archivos que el navegador entiende, y lo hace en milisegundos gracias a que arranca sin empaquetar todo de una vez. Cumple dos trabajos en este proyecto:
  • Andamio inicial — el comando de al lado genera toda la estructura de carpetas y archivos de un proyecto React desde cero.
  • Servidor de desarrollo — después, con npm run dev, sirve el proyecto en el navegador y recarga al instante cada vez que guardamos un archivo (reemplaza a Live Server).

El comando se ejecuta desde dentro de plantilla_proyecto/ (el mismo nivel donde están backend/ y frontend/). Vite arma sola la carpeta frontend-react/, con su propio proyecto React adentro.

Primera vez: pide instalar un paquete extra
La primera vez que se usa este comando en una máquina, npm no tiene aún la herramienta create-vite — pregunta si puede instalarla.
¿Ves algo distinto? Es normal
"command not found: npm" → Node.js no está instalado, o abriste una terminal antes de instalarlo. Cierra y abre una terminal nueva.
Número de versión distinto a create-vite@9.2.1 → normal, Vite se actualiza seguido. Sigue igual.
Terminal — dentro de plantilla_proyecto/
npm create vite@latest frontend-react -- --template react

Instalación · Paso 2 de 3

El asistente pregunta qué linter usar

Un linter es una herramienta que revisa el código mientras escribes y avisa errores de sintaxis antes de correrlo — no cambia cómo se ve la app, solo ayuda a detectar errores más rápido.

Terminal — asistente interactivo
│
◆Which linter to use?
│● Oxlint
│○ ESLint
│○ None
└
Elegir "Oxlint" (opción marcada por defecto)
Es el linter que trae Vite en su versión más reciente — no requiere ningún archivo de configuración extra, a diferencia de ESLint. Nos movemos con las flechas ↑↓ y confirmamos con Enter.
¿No ves flechas, solo números?
Algunas terminales viejas muestran la lista como texto plano numerado en vez del menú interactivo. En ese caso, escribe el número de la opción (Oxlint) y presiona Enter.

La última pregunta del asistente reemplaza tres comandos manuales (cd, npm install, npm run dev) por una sola confirmación.

│● Yes / ○ No

Terminal — resultado
Proyecto creado en frontend-react/
Dependencias instaladas
➜Local: http://localhost:5173/
¿Cómo sé que funcionó?
La terminal muestra la línea Local: http://localhost:5173/ y no se cierra sola. Mientras esa ventana quede abierta, el servidor sigue corriendo — así se ve tu proyecto en el navegador.
¿Dice "Port 5173 is already in use"?
No es un error: Vite abre automáticamente el siguiente puerto libre (5174, 5175...). Usa siempre la URL exacta que te muestre tu terminal, no asumas que siempre será 5173.
SLIDE 08 / 14
Instalación · Tailwind CSS

Ahora sí, instalar Tailwind

Con el proyecto React ya corriendo en localhost:5173, entramos a la carpeta nueva e instalamos dos paquetes — no es uno solo, cada uno cumple un rol distinto.

tailwindcss
El framework en sí: el motor que lee las clases del código (flex, p-4...) y genera el CSS final con solo las que se usaron.
@tailwindcss/vite
El plugin que conecta Tailwind con Vite — sin él, Vite no sabe que debe pasar los archivos por el motor de Tailwind al compilar.
Terminal — dentro de frontend-react/
cd frontend-react
npm install tailwindcss @tailwindcss/vite
Terminal — resultado
added 2 packages
Tailwind CSS instalado
Todavía falta un paso
Instalar el paquete no activa Tailwind por sí solo — falta registrar el plugin en vite.config.js y agregar el import en el CSS. Ese código exacto está en la guía paso a paso de hoy.

node_modules/
Código descargado de cada paquete instalado (React, Vite, Tailwind...). No se edita ni se sube a Git.
public/
favicon.svg e icons.svg — archivos estáticos que se sirven tal cual, sin pasar por Vite.
src/assets/
Imágenes que sí se importan desde el código (a diferencia de public/) — Vite las optimiza al compilar.
src/App.jsx
El componente principal. Aquí escribimos el navbar migrado en el Paso 5 de la guía.
src/App.css / src/index.css
index.css es donde va @import "tailwindcss" (Paso 2). App.css lo vamos a borrar — todo el estilo se hace con clases Tailwind.
src/main.jsx
Punto de entrada — conecta App.jsx con el HTML. Casi nunca se edita.
index.html
El HTML raíz — solo tiene un <div id="root"> vacío. React inyecta todo ahí dentro.
vite.config.js
La configuración de Vite. Aquí registramos el plugin de Tailwind (Paso 2 de la guía).
package.json / package-lock.json
package.json lista dependencias y comandos (npm run dev). package-lock.json fija la versión exacta de cada una — no se edita a mano.
.oxlintrc.json
Configuración del linter Oxlint que elegimos en el asistente — reglas de estilo de código, viene lista por defecto.
.gitignore
Lista de archivos y carpetas que Git ignora — por defecto ya excluye node_modules/.
README.md
Documentación básica generada por Vite. La vamos a reemplazar con información real del proyecto más adelante.
